## Later releases

The installer selector names no version, so a release needs no root step and no Apache change:
GitHub's latest moves to it on publication. Updating the pages is the procedure in
`ops/installer.md`: change `release` in `src/data/project.ts`, revise the pages, verify, and
publish `dist/` as the site's account. Until then `npm run verify:published` fails, naming the
release the installer gives and the one the site describes.

## Rollback

On the host, in `/opt/voxlucis.us/.deployments/20261010-v041`: move `/opt/voxlucis.us/dist` aside,
restore `previous-dist` to `/opt/voxlucis.us/dist`. Only if the installer selector must go back to
a pinned release (a root step): reinstall `previous-vhost.conf` as
`/etc/apache2/sites-available/voxlucis.us.conf`, run `apache2ctl configtest`, and reload Apache.
